# AI 연결과 심층 분석

## 구독 계정으로 사용

구독 계정은 로컬 모델과 다릅니다. 로컬 모델은 내 PC에서 직접 추론하는 Ollama 모델입니다.
Codex·Claude Code 연결은 내 PC의 공식 CLI를 통해 제공자의 모델을 호출합니다.

### Codex

[공식 CLI 설치](https://developers.openai.com/codex/cli/) 후:

```bash
codex --version
codex login
codex login status
```

설정에서 Codex를 선택하고 모델을 비워 CLI 기본값을 쓰거나 계정에서 사용 가능한 모델 ID를 지정합니다.
심층 모델은 별도로 지정할 수 있습니다. 비어 있으면 일반 모델을 사용합니다.
검증한 CLI 버전은 0.169.0입니다. 해당 버전 이상의 필요한 옵션을 지원하는 CLI를 사용하세요.
[공식 구독 인증](https://developers.openai.com/codex/auth/) · [비대화형 실행](https://developers.openai.com/codex/noninteractive/)

### Claude Code

[공식 설치](https://code.claude.com/docs/en/setup) 후:

```bash
claude --version
claude auth login
claude auth status
```

설정에서 Claude Code를 선택합니다. 모델 예시는 opus이며 실제 접근은 계정 권한에 따릅니다.
CLI 2.1.202의 옵션을 기준으로 연결했습니다. --safe-mode와 --json-schema 지원이 필요합니다.
이 개발 환경은 Claude 로그인이 없어 실제 제공자 추론을 검증하지 못했습니다.
어댑터 명령·응답 처리 테스트와 설치/로그인 상태 확인은 검증했습니다.
[공식 인증](https://code.claude.com/docs/en/authentication) · [프로그램 실행](https://code.claude.com/docs/en/headless)

로그인은 브라우저를 여는 공식 CLI에서 사용자가 직접 진행합니다.
대시보드는 토큰을 복사하지 않고 현재 로그인 상태만 확인합니다.
구독이 있다고 모든 모델·호출이 무제한 제공되는 것은 아닙니다.
API 키로 로그인한 CLI는 별도 과금 방식일 수 있으므로 CLI 인증 상태를 확인하세요.
SecureFlow는 공유 로그인 대행 서버나 공용 SaaS로 제공하는 구성이 아닙니다.

### Ollama

```bash
secureflow setup --ollama
```

기본 서버 http://127.0.0.1:11434, 모델 qwen2.5-coder:1.5b.
설치 프리셋은 코드용 qwen2.5-coder:1.5b와 보조용 qwen2.5:0.5b 두 개입니다.
모델 파일은 각각 약986MB와398MB이며 실제 메모리는 문맥 길이와 실행 환경에 따라 더 필요합니다.
[코드 모델](https://ollama.com/library/qwen2.5-coder:1.5b) · [보조 모델](https://ollama.com/library/qwen2.5:0.5b)
다른 모델은 먼저 Ollama에 설치한 뒤 이름을 설정합니다.
작은 모델의 추론 품질은 고급 모델과 다르며 다단계 호출만으로 정확도가 보장되지는 않습니다.
[Ollama Chat API](https://docs.ollama.com/api/chat)

## 로컬 앙상블과 실패 시 동작

진단 시작 화면에서 로컬 앙상블을 선택하면 두 모델에 동일 소스 발췌를 독립적으로 제공합니다.
앞 모델의 답을 뒷 모델에 주지 않으며 메모리 사용을 줄이기 위해 순차 실행하고 호출 후 모델을 해제합니다.
동일 파일/행에서 나온 가설을 모아 각 모델의 원래 위험 설명·수정안·테스트를 보존합니다.
모델 간 동의는 위치 기준이며 같은 결함임을 보장하거나 통계적 확률로 환산하지 않습니다.
같은 Qwen 계열의 관련 모델이므로 독립적인 오류를 낸다고 가정하지 않습니다.

- 두 모델 성공: complete, 모든 가설은 여전히 unverified.
- 한 모델 실패: partial, 성공 결과와 실패 이유를 함께 표시.
- 두 모델 실패: failed + standard_analysis_only, 일반 검사·리포트는 계속 생성.
- AI 미선택: disabled, 모델 호출 없음.
- CLI 미설치/로그인 만료/한도 초과/시간 초과/잘못된 JSON: AI 실패 표시, 일반 결과 유지.

기본 스캐너나 대상 자체가 실패하면 별도로 실패를 표시합니다. 이를 AI fallback으로 숨기거나 안전 판정하지 않습니다.
모든 가능한 OS·디스크·프로세스 장애를 복구한다는 의미는 아닙니다.

## 단계와 근거

일반 분석은 1회, 심층 분석은 최대 3회 순차 호출합니다.

1. review: 입력·민감 동작·접근 통제·상태 불변식의 근거 검토.
2. challenge: 이전 가설의 반례, 기존 방어 코드, 부족한 증거를 재검토.
3. synthesis: 유지할 가설, 구체적 수정안, 정상/비정상 회귀 테스트를 통합.

이는 같은 모델의 재검토이며 독립 전문가 합의나 정확성 보증이 아닙니다.
웹 검색을 수행하지 않으며 외부 최신 CVE 조사 기능도 아닙니다.
프롬프트와 검토 자료는 제한된 소스 발췌에 한정됩니다.

표준 분석은 최대5파일/파일당20줄/문자1만, 심층은 최대24파일/파일당60줄/문자3만2천입니다.
보안 관련 키워드가 있는 코드에 우선순위를 줍니다. 전체 저장소를 읽었다고 표시하지 않습니다.
.env·숨김 디렉터리·node_modules·실행 데이터·심볼릭 링크 파일을 제외하고 문자열 인증정보 패턴을 마스킹합니다.
이 마스킹은 완벽한 비밀정보 탐지기가 아니므로 원격 제공자에 보내도 되는 실습 소스만 연결하세요.
대상 계정 비밀번호·세션 증거는 입력으로 전달하지 않습니다.

반환된 파일/행이 실제 제공한 발췌에 있는지 검사합니다.
출력의 의미적 정확성·실제 exploitability는 별도 사람이 확인해야 합니다.
소스 발췌 SHA-256, 단계별 검토와 시간, 실패 상태를 최종 결과에 남깁니다.
뒤 단계가 실패하면 앞 결과를 partial로 보존하며 완료로 표시하지 않습니다.

## 실행 격리와 제한

Codex: 임시 빈 디렉터리, read-only, 사용자 설정·규칙 미로딩, 셸·플러그인·웹 검색 비활성.
Claude: 임시 빈 디렉터리, safe-mode, tools 빈 목록, MCP 빈 설정, 세션 저장 비활성.
대상 저장소 자체를 CLI 작업 디렉터리로 제공하지 않습니다.
권한을 무시하는 bypass 옵션은 사용하지 않습니다.

호출별 일반240초/심층300초 제한. CLI 시간 초과 시 자식 프로세스 그룹을 중단합니다.
CLI 인증은 기존 OS 사용자 계정의 권한이므로 강한 멀티테넌트 격리로 해석하면 안 됩니다.
빠른 리포트는 AI를 기다리지 않고, 통합 리포트에 완료·부분 실패·실패를 반영합니다.
